# Known issues, approximations and unknowns

Each item: classification, where it is implemented, and what would resolve it.

| ID | Item | Class | Where | Resolution path |
|---|---|---|---|---|
| U-1 | Ports 00/01 "raster/timer counter": MAME returns `rand()`; the game uses it for a palette-copy wait in the IRQ handler and as a pseudo-random value | APPROXIMATION (MAME behaviour, LFSR) | `nrc_st0016` (LFSR, advanced per read) | PCB measurement or logic-analyser capture |
| U-2 | NMI source: MAME pulses NMI at 6 fixed points per 384-line frame, only if IFF1 (MAME: "dirty hack") | APPROXIMATION (MAME rate/phase) | `nrc_irq` (all constants) | PCB measurement of NMI period (candidate: CRT reg `$70` = `$3E7` timer) |
| U-3 | Horizontal CRT register meanings (`$60-$65`) unknown; sync placement chosen by us: active 0-319, front porch 49, HSync 34 (4.75 us), back porch 52 dots; the line number advances at the HSync edge. Front porch >= 48 keeps HSync inside the blank at CRT Adjust H-Position -48 | MISTER-COMPATIBLE | `nrc_video_timing` parameters | PCB video capture; OSD CRT Adjust for per-monitor alignment |
| U-4 | Tilemaps: implemented per MAME 0.289 (no scroll, 64x32, base reg1 x $1000, priority/merge flags); tile attribute bits 7/6 are NOT treated as flips (nratechu's service-mode text has attr $40 and is only readable unflipped; MAME 0.289 draws it upside down, master mirrored). Scroll registers of tilemaps (MAME master reads reg0/reg2) not implemented - nratechu writes 0 | INFERENCE (readable text) | `nrc_render` | PCB photo of the service menu; other ST-0016 games |
| U-5 | Flip Screen (DIP SW2:7): the game writes CRT register `$74 = $59` (also `$70/$71 = $0308`, `$75 = $31`) and keeps drawing upright (MAME ignores the registers and shows the picture upright). Implemented as a 180-degree rotation of the displayed framebuffer whenever `$74` bits 7-5 are non-zero; the per-axis meaning of the bits and of `$70/$75` is not known | INFERENCE (as the owner's NA-1/NA-2 operator FLIP) | `nrc_st0016` (register), `nrc_core` (display read) | PCB check |
| U-6 | Frame render latency: one frame more than the PCB (framebuffer), fixed; character RAM not snapshotted during a render | DECISION | `nrc_render` | An in-vblank renderer was evaluated (2026-09-29) and rejected: worst measured frame (title, 2,975 visible tiles, 190,400 pixel RMWs, `scripts/mame/nrc_rendercost.lua` over 32,000 frames) vs 140,140 clocks between the IRQ and the first visible line; even a 2 px/clk redesign with overlapped fetches would need ~80-85 % of the window with no bound for unmeasured content, so latency could vary. Owner's rule: change only if every frame is guaranteed inside vblank. |
